---
title: Drill Tests
description: Playwright-style test suites for Auditaur-enabled Tauri apps, with UI, telemetry, and snapshot assertions.
---

`auditaur drill test` runs test suites against your real Tauri app. Tests click, type, and assert on the UI through the drive bridge, and also assert on telemetry: IPC calls, events, logs, and errors. The model follows Playwright: named tests, auto-retrying `expect`, hooks, retries, tags, snapshots, and a run report.

Use `drill test` for a growing suite. Use [`drill run`](/getting-started/drill-confidence-runs/) for a single readiness check.

## Write a suite

Suites live in `.auditaur/drills/*.drill.json`. The suite name defaults to the file stem.

```json
{
  "$schema": "https://auditaur.dev/schemas/drill.schema.json",
  "tags": ["@smoke"],
  "tests": [
    {
      "name": "successful command returns",
      "steps": [
        { "click": { "role": "button", "name": "Call successful command" } },
        { "expect": "#output", "toContainText": "Successful command returned" },
        { "expectIpc": "successful_command", "status": "ok", "count": 1 },
        { "expectNoErrors": true }
      ]
    }
  ]
}
```

The app needs `initAuditaur({ driveBridge: true })` in a debug build. See the [frontend API](/getting-started/frontend-api/).

## Run it

```bash
auditaur drill test --app my-app -- npm run tauri dev
```

The app name and launch command can come from `.auditaur/config.json` (`app`, `start`) instead. Each suite launches the app once, and its tests share it. Use `--attach` to drive an app that is already running.

A launched app counts as ready once its drive bridge responds, so `drill test` needs no `--require-drive-bridge`. The app needs `@auditaur/api` 0.7.0 or newer; an older bridge fails the suite at launch.

| Command | Purpose |
| --- | --- |
| `drill list` | List suites and tests (accepts the same filters as `test`). |
| `drill validate` | Check files against the schema, with "did you mean" hints. |
| `drill test` | Run tests and record a run. |
| `drill runs` | List recorded runs, newest first. |
| `drill show [id]` | Show a run (`latest` by default). |
| `drill locate <target>` | Suggest locators for what a CSS selector or locator matches in a running app. |

### Select tests

| Flag | Effect |
| --- | --- |
| `<filter>...` | Match a file path substring or a suite name. |
| `-g, --grep <regex>` | Match the title (`suite > test`) or `@tags`. |
| `--grep-invert <regex>` | Skip matching tests. |
| `--tag <tag>` | Only tests with this tag (repeatable). |
| `--last-failed` | Rerun the failed and unfinished tests from the newest finished run. |

In the test file, `"only": true` focuses tests, and `skip` and `fixme` (each takes an optional reason) leave tests out.

### Control the run

| Flag | Effect |
| --- | --- |
| `--retries <n>` | Retry failed tests. A test that passes on retry is reported as **flaky**. |
| `-x`, `--max-failures <n>` | Stop starting new tests after N failures. Cleanup still runs. |
| `-u, --update-snapshots[=mode]` | `none`, `missing` (default), `changed` (bare `-u`), or `all`. The value needs `=`. |
| `--trace <mode>` | `off` (default), `on`, or `on-first-retry`. Captures a screenshot and DOM snapshot after every step. |
| `--require-frontend` | Treat a launched app as ready only once its frontend reports telemetry. |
| `--timeout-seconds <n>` | Seconds to wait for a launched app to be ready (default 180). |
| `--junit <file>` | Also write JUnit XML for CI. |
| `--json` | Print the final run report as JSON. |

Ctrl+C stops the current test, still runs cleanup, and exits `130`. A second Ctrl+C exits immediately.

Exit codes: `0` all passed (flaky tests count as passed), `1` a test failed or did not run, `2` invalid drill files, `130` interrupted.

## Steps

Every step accepts `name` and `timeoutMs`.

| Kind | Steps |
| --- | --- |
| Actions | `click`, `dblclick`, `fill` + `value`, `type` + `value`, `press` (+ optional `target`; chords like `Control+s` or `ControlOrMeta+Shift+K`), `hover`, `select` + `value` or `values`, `check`, `uncheck` |
| Waits | `waitFor` + `state` (`visible`, `hidden`, `attached`, `detached`), `sleep`, `reload` |
| Other | `evaluate` (JavaScript), `run` (a command), `screenshot` (attachment only), `gate` (human-in-the-loop), `dialog` + `respond` (answer a [native dialog](#native-dialogs)) |
| UI assertions | `expect` + one of `toBeVisible`, `toBeHidden`, `toExist`, `toHaveText`, `toContainText`, `toHaveValue`, `toBeChecked`, `toHaveCount`, `toMatchAriaSnapshot`, `toHaveScreenshot` |
| Value assertions | `expectValue` (JavaScript) + one of `toEqual` (deep JSON equality), `toContain` (substring or array element), `toMatch` (regex string) |
| Telemetry assertions | `expectIpc` (+ `status`, `count`, `maxMs`), `expectEvent` (+ `count`), `expectLog` (+ `level`, `attributes`, `count`), `expectSpan` (+ `status`, `attributes`, `count`), `expectNoTelemetry` (+ `in`), `expectNoErrors` (+ `ignore`) |

Assertions retry until they pass or their retry window runs out: the suite's `expectTimeoutMs` (default 5s), or the step's own `timeoutMs`, like Playwright's `expect(..., { timeout })`. Add `"soft": true` to record a failure and keep going. Add `"not": true` to negate any assertion except snapshots and `expectNoErrors`. `toHaveText` and `toHaveValue` take a string or `{ "pattern": "regex" }`; `toContainText` takes a string.

### Keyboard input

`press` sends the events Playwright's `press` does on a US layout: `key`, `code`, `keyCode` and `location` (so `Space` is `key: " "`, `code: "Space"`), `keydown`, `keypress` for keys that produce text, and `keyup`. Name a key by its value (`Enter`, `ArrowDown`, `a`, `!`) or its code (`KeyA`, `Digit1`). As in Playwright, Shift changes a key named by code (`Shift+KeyA` is `A`) but not one named by character (`Shift+a` is `a`).

The events are synthetic (`isTrusted: false`), so the bridge also performs the browser's default action, unless the app calls `preventDefault()`:

| Key | Default action |
| --- | --- |
| `Tab`, `Shift+Tab` | Moves focus in tab order, firing `blur` and `focus`; wraps at the ends instead of leaving the webview |
| `Enter` | Clicks a button, link or `summary`; submits a text field's form; inserts a line break in a textarea or contenteditable |
| `Space` | Clicks a button, checkbox or radio on `keyup` |
| Text keys, `Backspace`, `Delete` | Edits a text field or contenteditable, with `beforeinput` first, as the browser's editing does |
| `Control+a` / `Meta+a` | Selects a field's content |

Other keys (arrows, `Home`, `End`, `PageUp`, `Escape`, …) only dispatch events: the bridge doesn't scroll, move a caret or close anything. That's enough for apps that handle those keys themselves, such as menus, lists and keyboard drag and drop. The reply reports `defaultAction` and `defaultPrevented`.

`fill` on a contenteditable (CodeMirror, ProseMirror, Lexical, …) selects its content and lets the browser replace it, as Playwright does, so the editor updates its own state. The step fails if the element's text doesn't end up equal to `value`, rather than passing without effect. A child of an editor fills the whole editor. A plain contenteditable without `white-space: pre` collapses repeated spaces and tabs, so such values fail honestly. In those cases drive the editor with `click` and `type`, or set it through `evaluate`.

`expectValue` re-evaluates its expression until the matcher passes, like Playwright's `expect.poll`; a throw counts as a miss. Use it for app state the DOM doesn't show:

```json
{ "expectValue": "localStorage.getItem('theme')", "toEqual": "dark" }
```

Telemetry assertions only see what the app recorded after the test started. Negative, exact-count, `expectNoTelemetry`, and `expectNoErrors` assertions check what has been recorded so far, so place them after the actions they cover.

`expectIpc` and `expectSpan` take a name or `{ "pattern": "regex" }`. A backend `#[auditaur::command]` span is named after its Rust function, so `"expectSpan": "save_project"` checks a command even when the frontend doesn't instrument it. Its `status` is `ok` when the command returns `Ok` (or a non-`Result` value) and `error`, with the serialized error as the message, when it returns `Err`; other spans set it through the OpenTelemetry `otel.status_code` / `otel.status_message` fields. A miss lists each span seen with its status. `attributes` maps attribute keys to exact values or `{ "pattern": "regex" }`. `expectNoTelemetry` fails if any log, span, IPC call, or event (narrow with `in`) contains the text or pattern anywhere in its data, which makes a privacy guard:

```json
{ "expectSpan": "chat.send", "status": "ok", "attributes": { "harness": "prompty" } },
{ "expectNoTelemetry": "ada@example.com", "in": ["logs", "spans", "ipc"] }
```

`run` runs a program (no shell) mid-test, with the same `args` and workspace-contained `cwd` as hooks, bounded by the step's `timeoutMs`. It passes when the exit code is `exitCode` (default 0) and `stdout`/`stderr` contain the given text or `{ "pattern": "regex" }`. Its output is attached to the step, as with hooks, so don't print secrets:

```json
{ "run": "git", "args": ["log", "-1", "--format=%an <%ae>"], "cwd": "${APP_PROJECT}", "stdout": "Ada <ada@example.com>" }
```

`${NAME}` in `args` and `cwd` (hooks and `run` steps) expands from suite `env` and `$AUDITAUR_DRILL_ENV_FILE`; other `${…}` text passes through to the command. A literal `cwd` is relative to the workspace and must stay inside it; a `cwd` built from a drill variable, such as a temp fixture, may be anywhere.

### Human gates

A `gate` step pauses the test until a person acts. It takes the same object as a [human-in-the-loop](/getting-started/human-in-the-loop-drills/) gate:

```json
{ "gate": {
    "name": "Approve sign-in",
    "instructions": "Finish the device-code sign-in in the browser.",
    "choices": [
      { "id": "done", "label": "Done", "outcome": "continue" },
      { "id": "blocked", "label": "Blocked", "outcome": "fail" }
    ] } }
```

Custom `choices` replace the default Continue, so include one with `"outcome": "continue"` or the test can't proceed. Answer it from the Progress page of the `auditaur-drills` canvas, the `respond_human_gate` MCP tool, or a response file; `drill test` never reads the terminal. A `skip` answer ends the test as skipped (in `beforeAll`, every test in the suite), `retry` keeps waiting, and `abort` fails it. The wait is off the test clock, as with Playwright's `page.pause()`: the gate's own `timeoutMs` (default 5 minutes) or a step `timeoutMs` bounds it, and the test's remaining budget is unchanged when it resumes.

### Native dialogs

Native file and message dialogs would block an unattended run, so a `dialog` step queues the answer to the next one the app opens, like Playwright's `page.once('dialog')`:

```json
{ "dialog": "save", "respond": "${FIXTURE}/deck.docx", "expectOptions": { "filters": [{ "name": "Word", "extensions": ["docx"] }] } },
{ "click": { "role": "button", "name": "Export" } }
```

| `dialog` | `respond` |
| --- | --- |
| `open` | a path, an array of paths, or `null` (cancel) |
| `save` | a path, or `null` (cancel) |
| `ask`, `confirm` | `true` or `false` |
| `message` | the clicked button's label (default `"Ok"`) |

Answers are used in order. `respond` strings expand `${NAME}` from the drill env; an unknown name fails the step. `expectOptions` matches the options the app passed like Playwright's `toMatchObject` (listed keys only; arrays element by element): `title`, `filters`, `defaultPath`, …, and for `ask`, `confirm`, and `message`, also `message`. The test fails if a dialog opens with nothing queued, opens a different kind or options than the next answer, or if an answer is never used. A `check dialogs` step attaches what the app asked for, redacted.

The app must open dialogs through `withDrillDialogs` from `@auditaur/api` 0.11.0 or later. Tauri's internal invoke can't be patched, so the wrapper replaces the plugin module:

```ts
// src/dialogs.ts — the app's only import of the dialog plugin
import * as dialog from '@tauri-apps/plugin-dialog';
import { withDrillDialogs } from '@auditaur/api';

export const { open, save, ask, confirm, message } = withDrillDialogs(dialog);
```

A lint rule keeps direct imports out:

```json
"no-restricted-imports": ["error", { "paths": [{ "name": "@tauri-apps/plugin-dialog", "message": "Import from src/dialogs instead." }] }]
```

Outside a drill the wrapper calls the real plugin. The runner arms it only in suites with `dialog` steps, for each test (and non-empty `beforeAll`/`afterAll`), on a lease that lapses shortly after the test's time budget, and re-arms it after `reload`; answers queued before a reload fail as dropped. A gate held past the lease disarms it, which fails loudly. The stub returns paths as-is: it doesn't add them to the fs or asset scope, so allow fixture paths in the app's capabilities.

### Locators

A locator is a CSS string or an object:

| Locator | Example |
| --- | --- |
| CSS | `"#output"` or `{ "css": "#output" }` |
| Role + accessible name | `{ "role": "button", "name": "Save", "exact": true }` |
| Text | `{ "text": "Throw frontend error" }` |
| Label / placeholder | `{ "label": "Email" }`, `{ "placeholder": "Search" }` |
| Test id | `{ "testId": "save" }` (`data-testid`) |

Add `nth` to pick one element when several match.

To find a good locator, point `drill locate` at a running app with a CSS selector. It suggests the most readable locator that matches only that element: test id, then role + name, label, placeholder, text, `#id`, and a CSS path last.

```bash
auditaur drill locate "li button" --app my-app
# 2 elements match:
#   {"exact":true,"name":"Edit","nth":0,"role":"button"}
#     <button> "Edit"
#   ...
```

## Hooks, timeouts, and modes

| Key | Where | Meaning |
| --- | --- | --- |
| `setup`, `teardown` | suite | Process hooks (`run`, `args`, `cwd`) that run before launch and after the app closes. |
| `beforeAll`, `afterAll` | suite | Steps that run once per suite. |
| `beforeEach`, `afterEach` | suite | Steps that run around every test. |
| `timeoutMs` | suite, test | Per-test timeout (default 30s). `"slow": true` triples it. |
| `expectTimeoutMs` | suite | How long assertions retry. |
| `retries` | suite, test | Overrides `--retries`. |
| `expectFail` | test | The test passes only if it fails. |
| `env` | suite | Environment variables for the app launch, hooks, and `run` steps. |

Setup hooks can add computed values, such as a temp fixture path, by appending `KEY=VALUE` lines to the file named by `$AUDITAUR_DRILL_ENV_FILE`, like `$GITHUB_ENV`. Later values win, and the launch, later hooks, and `run` steps see them. The file is deleted when the suite ends. When the config's `start` command provides port variables, those win. An attached app (no launch command) never sees suite environment.

```json
"env": { "VITE_STARTUP_VIEW": "editor" },
"setup": [{ "name": "fixture", "run": "node", "args": ["scripts/make-fixture.mjs"] }]
```

```js
// scripts/make-fixture.mjs
fs.appendFileSync(process.env.AUDITAUR_DRILL_ENV_FILE, `APP_PROJECT=${dir}\n`);
```

### A suite is one app launch

Each suite launches the app once; its tests, retries included, share that instance, and the app closes before the next suite starts. That keeps suites fast, so state carries between tests:

- Reset what a test depends on in `beforeEach`: navigate home, clear storage, or `run` a script that resets fixtures.
- Put work that needs a fresh process, such as first-run flows or startup flags in `env`, in its own suite.
- For full per-test isolation, give each test its own single-test suite, at the cost of a launch per test.

If the app exits or restarts mid-suite, the suite's remaining tests stop rather than running against a different instance.

## Snapshots

`toMatchAriaSnapshot` compares the element's accessibility tree as YAML. `toHaveScreenshot` compares pixels, using `mask`, `threshold`, `maxDiffPixels`, and `maxDiffPixelRatio`. Name a snapshot by giving it a string (`"toHaveScreenshot": "home"`), or use `true` to get an auto-numbered name.

Baselines live beside the suite, in `__snapshots__/<suite>/`. ARIA baselines (`<name>.aria.yml`) are shared across platforms. Screenshots are per OS (`<name>-<os>.png`) and depend on DPI and fonts, so tag them (for example `@visual`) and skip them on machines that don't match the baseline.

A missing baseline is written and the test still fails, so review the new baseline and commit it. In CI, pass `--update-snapshots=none`.

## Run folders

Each run is recorded under `.auditaur/drill-runs/<runId>/`. Auditaur gitignores the folder and prunes it to the 20 newest runs, never deleting a run that is still in progress. Each launched app's stdout and stderr go to `app-<n>.log` in the run (not redacted); a launch failure quotes its end and attaches the last 64K characters to the launch step. While the app launches, the canvas shows its latest output line under the "launch app" step, so a long first compile is visible. If readiness times out while that line is build activity (cargo's `Compiling …` or `Building [==> ] n/m` progress, …), the error quotes it and says the app was still building; raise `--timeout-seconds` or `readiness.timeoutSeconds`.

```text
run.json                         run report, updated as the run progresses
events.jsonl                     live event stream
tests/<testId>/attempt-<n>/      attempt.json, plus screenshots, ARIA snapshots, and telemetry
drill-test.log                   console output, for runs started by the MCP drill_test tool
```

Failed steps attach (where `<n>` is the 1-based step number shown in reports) `step-<n>-failure.png`, `step-<n>-failure-dom.json`, `step-<n>-failure-aria.yml`, the last 64K characters of app output (`step-<n>-failure-app-output.log`), and `step-<n>-failure-evidence.json`, which lists what was captured and why anything is missing. Evidence is captured even when the app crashed, so its output survives. If the app dies or is relaunched mid-run (for example a `tauri dev` rebuild), the test fails with `app exited: it restarted mid-run (pid A → B …)` and the remaining tests stop, instead of every step timing out against the old instance. With `--trace`, other steps attach `step-<n>-trace.png` and `step-<n>-trace-dom.json`; capture time is not counted in step durations. `on-first-retry` traces only the first retry, so passing runs stay cheap.

The format is versioned by [`drill-run.schema.json`](/schemas/drill-run.schema.json). `drill show`, MCP tools, and canvases read it without recomputing anything.

A running test command stops gracefully, like Ctrl+C, when a `cancel.request` file appears in its run folder.

## From an agent

`auditaur mcp` exposes the same workflow as tools, so an agent can run and inspect drills without blocking:

| Tool | Does |
| --- | --- |
| `drill_list`, `drill_validate` | Same as the CLI commands. |
| `drill_test` | Starts `drill test` in the background and returns its `runId`. |
| `drill_runs`, `drill_show` | Lists runs; shows one run, or one test's attempts with `test`. |
| `drill_cancel` | Stops a running run. |

Poll `drill_show` until `status` is no longer `running`. See [MCP Tools](/reference/mcp-tools/).

## In the Copilot app

The `auditaur-drills` canvas is one panel with a tab per page. Links between pages (**Open in Trace**, for example) switch tabs in the same panel, and the panel remembers its page across reloads.

Install it one of two ways:

| Install | Command | Serves | Updates |
| --- | --- | --- | --- |
| Copilot plugin | `copilot plugin marketplace add sethjuarez/auditaur`, then `copilot plugin install auditaur@auditaur` | The repo the session runs in | `copilot plugin update auditaur` |
| Committed copy | `auditaur init extension` | The repo it is committed in | `auditaur init extension --force`, then reload extensions |

The plugin also ships the `auditaur-debug` skill and the `auditaur mcp` server (it runs `auditaur` from `PATH`, so skip a manual MCP entry). When a repo commits its own copy, the plugin copy stays idle so the canvas has one provider. The `health` action reports which copy runs (`install`), its `version` and `versionSource`, `onDiskVersion` (the version now on disk), and the CLI version. `versionSource` is `plugin`, `init` (the `installed.json` stamp `init extension` writes), or `bundled` (the `version.json` every release ships, e.g. a copy installed from a release tag). The panel warns when the canvas and CLI versions differ, with the fix for that install.

A running canvas keeps its loaded code: reopening the panel or touching its files reuses the same extension process, and `init extension --force` can't restart it. After updating any copy, start a new session, or reload extensions if your host offers it. In Copilot, `install_extension` reloads but won't overwrite an installed extension, so remove the installed copy first, then install the new one. Until a reload, `health` reports `stale: true` and the panel shows a "changed on disk" warning naming both versions.

To try another version of the plugin in a consumer app, point the marketplace at it:

| Version | Marketplace source |
| --- | --- |
| Release | `sethjuarez/auditaur` |
| Branch or PR | `sethjuarez/auditaur#<branch>` |
| Local checkout | `<checkout>` (a path; loads live, edits apply in the next session), or one session only: `copilot --plugin-dir <checkout>\plugins\auditaur` |

Only one source per name is registered, so switch with `copilot plugin marketplace remove auditaur` (this also uninstalls the plugin), `add` the new source, and `install auditaur@auditaur` again. Set `AUDITAUR_BIN` to the matching CLI build, e.g. `<checkout>\target\debug\auditaur.exe`.

| Page | Shows | Agent actions |
| --- | --- | --- |
| Tests | Every suite and test with its latest result, recent results, flaky and slow badges, and the last error. Run everything, a suite, one test, or the last failures; **Cancel run** stops it. | `get_summary`, `refresh`, `run`, `cancel` |
| Progress | One run live: suites, tests, and steps ticking, with waiting gates at the top. | `get_status`, `respond_gate`, `cancel` |
| Trace | One test attempt: a step timeline with IPC, event, log, and frontend-error ticks, plus each step's screenshots, DOM snapshot, and telemetry. Defaults to the newest run's first failed test. | `get_trace` |
| Snapshots | ARIA line diffs and screenshot diffs (side by side, slider, or pixel diff). **Accept as new baseline** overwrites the baseline once the run has finished; output that never stabilized cannot be accepted. | `get_snapshots`, `accept_snapshots` |
| Coverage | Which IPC commands and events the tests exercised. Commands count frontend invokes plus backend `#[auditaur_command]`/`instrument_ipc` spans that no recorded invoke made, so commands an app calls without `@auditaur/api`'s `invoke` still count (backend spans carry `tauri.command` once the app upgrades `tauri-plugin-auditaur` past 0.4.15). Commands are measured against the app's registered commands, read from `generate_handler!` in `src-tauri/src` (or `coverage.commands` in `.auditaur/config.json`), so commands no test called show as unexercised, and a called command missing from that list is marked "not registered". **Compare with app telemetry** adds sessions from `auditaur apps`, so what they recorded but no test touched shows as unexercised; it suggests the stores of the app the run launched. Without either, commands and events are plain "touched" counts, never a percentage. Same data as `auditaur drill coverage [run] [--db <telemetry.sqlite>] [--commands <path>]`. | `get_coverage`, `list_app_stores`, `set_sources` |
| Gate | One pending `auditaur drill` [human gate](/getting-started/human-in-the-loop-drills/#copilot-canvas). The tab shows only while in use. | `show_gate`, `get_gate`, `answer_gate` |

Every page also takes `navigate`, `get_view`, `set_view`, `screenshot`, and `health`.

Open input, all optional:

| Field | Meaning |
| --- | --- |
| `cwd` | Folder holding `.auditaur/drills`, relative to the repo root. |
| `cli` | Path to `auditaur`; defaults to `$AUDITAUR_BIN`, then `PATH`. |
| `run` | `{ app, command, args }` for the run buttons: `--app`, the launch command after `--`, and extra `drill test` arguments. |
| `dbs` | Telemetry stores Coverage compares against. |
| `route` | First page, e.g. `/trace?run=<runId>&test=<testId>`. |
| `gate` | A `list_pending_human_gates` entry; opens on the Gate page. |

The canvas is one React + [Primer](https://primer.style/react) bundle, so they match the Copilot app's look and theme. Its source is `packages/drills-ui`. After editing it, run `npm run build` to rebuild the committed `ui/app.js` and `ui/app.css`. CI fails if the bundle is out of date.

## CI

Build a debug app, which embeds the frontend and keeps the drive bridge on, then run the drills against the binary:

```yaml
- run: npm run tauri build -- --debug --no-bundle
- run: >
    auditaur drill test --grep-invert '@visual' --update-snapshots=none
    --junit drill-results.xml --app my-app
    -- src-tauri/target/debug/my-app
```

Upload `drill-results.xml` and `.auditaur/drill-runs/`. `upload-artifact` needs `include-hidden-files: true` for that folder. The Auditaur repository's `tauri-drills` CI job runs the dogfood suites this way.
