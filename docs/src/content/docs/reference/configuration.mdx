## Rust plugin builder

| Method | Purpose |
| --- | --- |
| `service_name(name)` | Overrides the stored service name. |
| `session_name(name)` | Adds a human-readable session label to the stored session row. |
| `redact_defaults(bool)` | Enables or disables default key-based redaction. |
| `max_session_bytes(bytes)` | Enables best-effort pruning after frontend batches when the SQLite database exceeds this size. |
| `allow_release_builds(bool)` | Allows collection outside debug builds. |

`capture_full_payloads` and `max_payload_bytes` exist in the internal Rust config type for a future plugin-side payload policy pass. The current frontend package owns payload capture and payload summary limits.

## Frontend package

| Option | Default | Purpose |
| --- | --- | --- |
| `serviceName` | required | Frontend service name. |
| `serviceVersion` | none | Optional frontend service version stored on emitted records. |
| `instrumentConsole` | `true` | Capture console logs. |
| `instrumentErrors` | `true` | Capture uncaught errors and unhandled rejections. |
| `instrumentTauriInvoke` | `true` | Wrap Tauri command calls. |
| `propagateTauriInvokeTraceContext` | `true` | Send W3C `traceparent` plus the reserved compatibility invoke argument through wrapped Tauri invokes. |
| `instrumentTauriEvents` | `true` | Wrap event emit/listen calls. |
| `captureFullPayloads` | `false` | Store full invoke args and event payloads (key-redacted) when they fit within the size cap. |
| `payloadSummaries` | `true` | Store text summaries of invoke args/results and event payloads. Set `false` to store no payload content. |
| `redactKeys` | `[]` | Extra keys to redact, on top of the defaults (`password`, `token`, `key`, `session`, …). Case-insensitive, any depth. |
| `redactPayload` | none | `(payload, { kind, name }) => unknown` rewrites a payload before key redaction; `kind` is `invokeArgs`, `invokeResult`, or `eventPayload`. If it throws, the payload is stored as `[REDACTED]`. |
| `redactErrorMessage` | none | `(message, { name }) => string` rewrites a failed invoke's or emit's error message before it is stored (object errors are key-redacted first). If it throws or returns a non-string, the message is stored as `[REDACTED]`. |
| `maxPayloadBytes` | `16384` | Bounds captured payload summaries and payload values. |
| `batchIntervalMs` | `1000` | Flush cadence. |
| `maxBatchSize` | `64` | Flush when the in-memory batch reaches this size. |
| `onExportError` | none | Callback for failed exports with attempted, queued, retained, and dropped record counts. |
| `driveBridge` | `false` | Enables the debug/test in-app drive bridge. Pass `true` or `{ windowLabel, pollIntervalMs }`. |

Important defaults: redaction is enabled (payload summaries are key-redacted before they leave the webview; console log bodies and invoke/emit error strings are not, unless you set `redactErrorMessage`), full payload capture is disabled in the frontend package, retention defaults to 256 MiB, and release builds are blocked unless explicitly allowed.

Default redaction keys cover credentials only. Summaries still contain other values, such as chat text or emails. Name those fields, or rewrite whole payloads:

```ts
initAuditaur({
  serviceName: 'my-app',
  redactKeys: ['email', 'transcript'],
  redactPayload: (payload, { name }) => (name === 'save_chat_session' ? '[omitted]' : payload),
  redactErrorMessage: (message) => message.replace(/\S+@\S+/g, '<email>'),
  // or record no payload content at all: payloadSummaries: false
});
```

To unit-test these settings without a running app, `recordedPayload(config, kind, name, value)` and `recordedErrorMessage(config, name, error)` return exactly what recording would keep:

```ts
import { recordedErrorMessage, recordedPayload } from '@auditaur/api';

expect(recordedPayload(config, 'invokeResult', 'list_variations', result).summary).not.toContain('@');
```

Auditaur is intended to be dev/debug first; production collection should be an explicit product decision with consent, redaction, retention, and export handling reviewed.
